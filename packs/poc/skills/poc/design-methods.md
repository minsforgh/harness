# POC 설계 방법론

단계별 점검 질문이다(poc 스킬). 해당 단계에서 그 절만 읽는다. "P4" 절의 표는 P1에서 첫 마일스톤을 고를 때도 쓴다. 책과 강연의 문장을 옮기지 않고 POC에 맞게 다시 썼다.

## 쓰는 규칙

- 질문마다 답을 길게 쓰지 않는다. 답이 작업 순서(`docs/tasks.md`), 튜닝, 판정 결론 중 하나를 바꾸면 반영하고, 아무것도 바꾸지 않으면 버린다.
- 사용자에게는 결론이 갈리는 질문만 묻는다. 나머지는 추천안을 문서에 쓰고 P2 승인 때 보게 한다.
- 이 질문들은 무엇을 시험할지 좁힐 뿐이다. 재미 판정은 사람의 플레이로 한다.

## P4 구현: 위험한 것부터 확인

가장 불확실한 가정에 맞춰 먼저 확인할 것을 고른다.

| 가정의 종류 | 먼저 만들 것 |
|---|---|
| 규칙과 수치의 재미 (배합, 경제, 빌드) | **규칙 확인 화면**: 아트와 이동 없이 버튼과 숫자로 규칙을 조작해 보는 씬 하나. 규칙은 순수 C#으로 만들어 본 게임에 그대로 쓰고, 화면만 버린다 |
| 조작과 손맛 (액션, 플랫폼) | 플레이스홀더 캐릭터와 빈 방 하나. 입력 반응, 가속, 피드백을 먼저 튜닝한다 |
| 읽히는지 (명료성, 테마와 규칙의 일치) | 핵심 행동 하나가 보이는 최소 장면. 규칙을 읽히게 하는 표현(색, 피드백, 반응)만 먼저 넣고, 설명 없이 해 보게 한다 |
| 수치 균형, 지배 전략 여부 (깊이) | Unity보다 싼 수단: 시트나 계산 스크립트로 선택지별 결과를 비교한다. 답이 나오면 규칙 확인 화면으로 넘어간다 |
| 그 밖의 경험 (분위기, 서사) | 그 경험이 담긴 한 장면을 가장 싸게 만드는 방법을 사용자와 정한다 |

- 이 프로토타입이 답할 질문이 무엇인가? 답에 필요 없는 품질은 잊고 빨리 만든다.
- 목표와 점수가 없어도 만지작거리는 것 자체가 즐거운가? 핵심 조작이나 규칙을 장난감처럼 가지고 놀아 본다.

첫 확인에서 가정이 틀렸으면 다음 작업으로 넘어가지 않고 사용자에게 알린다.

## P5 플레이테스트: 말보다 행동

**진행**

1. 시작 전 보고 싶은 신호를 다시 보고, 이번 테스트를 정한다: 왜 하는가, 누가 하는가, 어디서 하는가, 무엇을 볼 것인가, 어떻게 정보를 얻을 것인가. 플레이 후에 기준을 바꾸지 않는다.
2. 조작법 외에는 설명하지 않는다. 막혀도 바로 돕지 않고 어디서 왜 막혔는지 본다.
3. 플레이 중에 생각을 말로 해 달라고 부탁한다.
4. 끝나고 묻는다: 무엇을 하려고 했나요? 언제 가장 재밌었고 언제 지루했나요? 무엇을 고민했나요? "재밌었어요?"처럼 답이 정해진 질문은 하지 않는다.

**기록과 판단**

- 관찰한 행동과 플레이어의 의견을 나눠 적는다. 둘이 다르면 행동을 더 믿는다.
- 플레이어의 해결책보다 그 말이 나온 문제를 본다. 수치로 풀 수 있는지 먼저 본다.
- 관찰을 기획 문서의 관점으로 다시 읽는다: 이해했는가(명료성), 다르게 느꼈는가(독창성), 고민했는가(깊이), 주 재미의 신호가 보였는가(재미). 어느 관점의 문제인지에 따라 고칠 곳이 다르다.
- 보고 싶은 신호로 결론을 낸다: 계속(튜닝 후 재시험), 피벗(배운 것과 바꿀 가정을 적는다), 중단.

**튜닝 점검** (결론이 계속일 때)

- 바라는 감정과 실제로 관찰된 감정의 차이는 무엇인가?
- 지금 무엇을 해야 하는지 알 수 있고, 결과가 바로 보이는가? 도전이 지루함과 불안 사이에 있는가?
- 한 판 동안 흥미가 어떻게 오르내리는가? 어디서 처지는가?
- 작은 행동에도 게임이 충분히 반응하는가?
- 재시험 전에 위험 목록과 함께 내 열정도 다시 본다. 아직 이 게임을 더 만들고 싶은가? 테스트와 수정의 한 바퀴를 빠르게 도는 것을 우선한다.

## 출처

번호는 *The Art of Game Design* 3판 렌즈 기준이다(1판과 번호가 다르다). 책 본문이 아니라 공개 정리 자료를 교차 확인한 내용을 다시 썼다.

- P4 질문에 답하는 프로토타입: 8장. 장난감: #17 Toy
- P4 규칙 확인 화면: 시뮬레이션 중심 게임에는 수직 슬라이스가 잘 안 맞는다는 비판(Borut Pfeifer)을 받아 Mark Cerny, The Method의 첫 플레이어블 판정과 함께 쓴다
- P5 다섯 질문: #103 Playtesting. 튜닝 점검: #1 Emotion, #21 Flow, #69 Interest Curve, #64 Juiciness, #18 Passion, 루프의 법칙(8장)
- 일반 관행으로 쓴 것: 설명 없는 관찰, 생각 말하기, 행동 우선, 질문 방식, 조작감 우선. 생각 말하기와 인터뷰 요령이 책 28장에 있다는 정리 자료는 한 곳뿐이라 책 내용으로 단정하지 않는다. Tracy Fullerton, *Game Design Workshop*의 Playtesting 장과 Steve Swink, *Game Feel*도 가까운 자료지만 일치 여부는 확인하지 않았다
