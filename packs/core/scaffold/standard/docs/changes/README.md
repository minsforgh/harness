# 진행 중인 큰 변경

> 이 파일은 형식 안내다. 여러 시스템에 걸치거나 한 세션에 끝나지 않는 작업만 여기에 폴더를 만든다. 작은 수정과 시스템 하나의 동작 변경은 폴더 없이 커밋과 그 시스템 문서 수정으로 끝낸다.

## 폴더

`docs/changes/<YYYY-MM-DD>-<slug>/` (시작한 날, slug는 영문 소문자와 `-`)

| 파일 | 내용 |
|---|---|
| `proposal.md` | 왜(문제), 무엇(바뀌는 동작), 비목표, 바뀔 현재 상태 문서 목록, 확인 방법. 사람이 비목표와 확인 방법을 본다 |
| `tasks.md` | 할 일 목록(`- [ ]`, `- [x]`). 진행하면서 체크한다. 다음 세션이 여기서 이어 간다 |
| `design.md` | (선택) 여러 안 중 고른 구조. 되돌리기 어려운 것은 ADR로 올린다 |

## 진행하는 동안

- 현재 상태 문서(시스템 문서, 구조 지도, 개요, 용어)는 끝날 때 몰아서가 아니라 동작을 바꾼 커밋마다 고친다. 이 폴더에는 왜, 계획, 할 일만 둔다
- 문서는 1~2쪽으로 쓴다. 300줄이 넘으면 커밋 전 검사가 알린다

## 끝낼 때

1. proposal의 "바뀔 현재 상태 문서"가 다 고쳐졌는지 본다. 남은 것이 있으면 지금 고친다
2. design.md에 되돌리기 어려운 결정이 있으면 `docs/adr/`로 올린다
3. 폴더를 이 폴더의 `archive/` 아래로 옮긴다(없으면 만든다). archive는 기록이라 검사하지 않고, 다시 고치지 않는다

tasks.md의 할 일이 다 체크되면 커밋 전 검사가 archive로 옮길 때라고 알린다.
