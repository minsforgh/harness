# 결정 기록 (ADR)

> 이 파일은 형식 안내다. 결정은 이 폴더에 하나에 파일 하나로 쓴다. 결정 목록은 이 폴더의 파일 목록이다.

## 언제 쓰나

셋이 모두 맞을 때만 쓴다. 하나라도 아니면 쓰지 않는다.

1. 되돌리기 어렵다: 나중에 마음을 바꾸는 비용이 크다
2. 맥락 없이 보면 의아하다: 나중에 코드를 본 사람이 왜 이렇게 했는지 궁금해한다
3. 실제로 저울질했다: 다른 안이 있었고 이유가 있어 하나를 골랐다

grilling 결론도 셋이 맞는 결정마다 하나씩 쓴다. 맞지 않는 결론은 해당 현재 상태 문서에만 반영한다. 질문 목록과 과정은 옮기지 않는다.

## 파일

- 한 파일에 결정 하나, 1~2쪽. 작은 결정 여럿을 한 파일에 묶지 않는다
- 이름: `NNNN-<slug>.md`. 번호는 이 폴더의 가장 큰 번호 + 1, 다시 쓰지 않는다. slug는 영문 소문자와 `-`. 병렬 브랜치에서 같은 번호가 생기면 나중에 합치는 쪽이 다음 번호로 바꾼다
- 한 번 쓴 결정은 고치지 않는다. 바뀌면 새 ADR을 쓰고, 옛 ADR의 상태 줄만 `superseded by ADR-NNNN`으로 바꾼다
- 상태 줄이 없으면 accepted로 본다(domain-modeling 스킬은 상태 없이 쓰기도 한다)
- 결정으로 바뀐 동작은 해당 현재 상태 문서(개요, 구조, 시스템 문서)의 그 자리에 반영한다

## 형식

```
# <결정 제목>

- 상태: accepted
- 날짜: YYYY-MM-DD

<1~3문장: 맥락, 결정, 이유>

## 버린 안 (기억할 가치가 있을 때만)

- <안>: <버린 이유>

## 결과 (뻔하지 않을 때만)

- <이 결정 때문에 따라오는 것>
```
