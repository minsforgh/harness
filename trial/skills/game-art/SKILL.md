# game-art

상태: 시험 중. 쓸 때마다 아래 "시험 기록"에 한 줄 남긴다.

MaxwellDemon에서 주인공, 보스 4, 적 2의 컷아웃 리그와 보스방 배경 4곳을 이 순서로 만들었다(절차 원본: MaxwellDemon `Assets/Entropy/Art/Characters/리그 절차.md`, `docs/배경 절차.md`). 그림 생성은 매번 달라지므로, 지시와 기준 그림과 판 번호를 파일로 남겨야 같은 세계의 그림을 다시 얻을 수 있다.

## 프로젝트 값

프로젝트의 아트 문서(AGENTS.md "값" 표의 아트 칸, 없으면 `docs/art/`의 의뢰서나 `docs/art.md`)에 아래를 적는다. 없으면 `templates/art.md`를 복사해 채우고 사용자에게 확인받는다.

| 무엇 | 왜 |
|---|---|
| 화풍 한 줄과 공통 스타일 줄(영어) | 모든 지시 끝에 붙여 같은 세계의 그림이 되게 한다 |
| 기준 그림 경로 | 확정된 디자인 시트. 이후 모든 생성에 참고 이미지로 첨부한다 |
| 생성 방식: 에이전트가 Codex를 부름 / 사용자가 생성 | 사용자가 정한다. 정해지지 않았으면 에이전트가 부르는 쪽을 제안한다(MaxwellDemon에서 확인한 방식) |
| 모델 | 늘 `-m`으로 넘긴다. 빼면 Codex 설정 기본값으로 돌아 사용자가 정한 모델(비용)과 달라진다(Arrowhead에서 겪음) |
| 그림 폴더 규칙 | 대상마다 `<Art>/<종류>/<이름>/`에 지시와 판별 그림을 둔다. 생성 로그와 보고는 그 아래 `gen~/`(Unity가 가져오지 않는 폴더)에 둔다 |
| 배경색 | 오리기 쉬운 단색. MaxwellDemon은 밝은 회색으로 확인했다 |

## 순서

1. **대상과 우선순위**: 무엇을 그릴지 목록을 만든다. 디자인을 고정할 기준(주인공 디자인 시트)을 먼저, 규칙과 무관한 아이콘은 언제든, 게임 판정과 모양이 맞아야 하는 것(부위가 있는 적)은 판정 목록을 사용자와 맞춘 뒤에 그린다. 그림을 다시 뽑는 것보다 데이터를 고치는 것이 싸다.
2. **지시 파일**: 대상 폴더에 `prompt_v<판>.md`를 `templates/prompt.md` 형식으로 쓴다(한국어 의도, 첨부 설명, 저장과 보고 규칙, 영어 프롬프트). 레퍼런스 작품과 캐릭터의 이름은 프롬프트에 넣지 않고 가져올 특징(구도, 차림, 색)으로 풀어 쓰며 "Original design"을 넣는다. 이름을 넣으면 그 캐릭터를 베끼는 쪽으로 끌려간다.
3. **생성**:
   - 에이전트가 부를 때(대상 폴더에서, 오래 걸리니 뒤에서 돌린다):
     ```
     mkdir -p gen~
     echo "prompt_v2.md 파일을 읽고 거기 적힌 대로 수행해라. 첫 번째 첨부는 <무엇>, 두 번째 첨부는 <무엇>이다." \
       | codex exec -m <모델> -s workspace-write --skip-git-repo-check -C . -i <기준 그림> [-i <참고 2>] -o gen~/gen_report_v2.txt - > gen~/gen_log_v2.txt 2>&1
     ```
     지시는 표준 입력(`-`)으로 넣는다. `-i` 뒤에 바로 쓰면 지시가 이미지 경로로 먹힌다. Codex는 내장 이미지 생성으로 그려 이 폴더에 저장한다. 로그를 Assets 안 보통 폴더에 쓰면 쓰는 도중에 Unity가 가져가 콘솔 오류("processed bytes does not match file size")가 남는다. 보고에 쓴 모델을 적는다.
   - 사용자가 생성할 때: 지시 파일 경로, 첨부할 기준 그림, 저장할 파일 이름과 폴더를 짧게 알려 주고 기다린다.
   - 첫 판은 안 2~3개(`_a`, `_b`)로 뽑는다. 한 장만 보면 고칠 점을 말하기 어렵다.
4. **고르기**: 결과를 사용자에게 보여 주고(이미지 읽기, 다른 기기면 SendUserFile) 고르게 한다. 고친 판은 판 번호를 올려 새 지시 파일로 뽑고, 앞 판을 참고 이미지로 넣는다. 고른 기준 그림은 아트 문서에 경로를 적는다. 버린 판은 사용자가 정리를 말할 때 지운다.
5. **배경 오리기**: `templates/cut_solid.py`(단색 배경 위 그림을 바깥 배경과 이어진 곳만 투명하게 자름, numpy와 Pillow)를 프로젝트의 도구 폴더(Unity는 `Tools~`처럼 가져오지 않는 폴더)에 복사해 쓴다. 투명 PNG로 받았으면 건너뛴다.
6. **움직일 캐릭터**: 아래 "조립 그림 기준 컷아웃"을 따른다. 움직이지 않는 그림(초상, 아이콘, 배경)은 건너뛴다.
7. **들이기**: Sprite로 가져온다. PPU는 발밑부터 머리 끝까지 픽셀 높이를 원하는 유닛 높이로 나눈다. 판정(콜라이더, 부위 영역)이 있으면 그림에 맞춰 옮기고, 플레이 화면을 캡처해 크기, 위치, 판정이 맞는지 본다. 임시 그림을 바꿨으면 지운 임시 그림을 보고에 적는다.
8. 시험 기록을 한 줄 남긴다.

## 조립 그림 기준 컷아웃

부위 분리 시트의 조각을 이어 붙이지 않는다. 시트의 조각은 조립 그림과 비율이 달라 붙이면 관절이 어긋난다(MaxwellDemon 첫 판 세 캐릭터에서 겪음). 대신:

1. 조립된 전신 한 장을 기준(`<이름>_v<판>_assembled.png`)으로 둔다.
2. Codex 편집으로 같은 구도에서 일부를 지운 판을 만든다: 팔을 지우고 어깨를 이어 그린 판(`_noarms`), 장치나 소품을 지운 판(`_body`), 인물을 지우고 가려진 장치를 이어 그린 판(`_devices`). 지시에 "자세, 크기, 위치, 선, 색, 캔버스 비율을 바꾸지 말 것, 지운 자리는 같은 단색 배경"을 넣는다.
3. 모든 조각을 같은 그림 좌표에서 오린다. 팔은 있는 판과 없는 판의 차이로 고르고, 차이가 지저분하면 팔 색으로 고른 뒤 외곽선만큼 넓힌다. 피벗은 관절(어깨, 목 아래, 경첩 쪽 끝).
4. 부위를 Transform 계층으로 묶고 클립을 만든 뒤, 대표 자세를 찍어 관절이 떨어지는지 본다. 크게 움직인 자세에서 잘 드러난다.

> 예시 도구: MaxwellDemon `Assets/Entropy/Art/Tools~/`의 `rig_common.py`(리그 텍스트, 미리보기), `rig_<이름>.py`(캐릭터별 오리기), `unity/build_visual.csx`, `clips_*.csx`, `shot.py`. 캐릭터마다 다르므로 복사보다 참고용이다.

## 함정

- Codex는 해상도를 바꿀 수 있다(높이 1024가 1850 안팎으로). 같은 기준에서 나온 편집 판끼리 크기가 같은지 먼저 확인하고, 1픽셀 어긋나면 오리는 스크립트에서 맞춘다.
- 결과 그림 가장자리 1~2픽셀이 밝은 테두리일 때가 있다. 그대로 자르면 바깥 배경 채우기가 시작되지 않아 배경이 통째로 남는다. 자르기 전에 가장자리를 배경색으로 덮는다.
- 배경과 비슷한 밝은 색(은색 하이라이트)은 갇힌 배경 구멍으로 잘려 나간다. 그런 캐릭터는 구멍 크기 기준(`hole_min`)을 낮추지 않는다.
- 몸과 함께 움직일 부위(뒤팔, 등 장식)는 몸 아래 자식으로 둔다. 숨쉬기처럼 몸 배율을 바꾸는 클립이 있으면 머리와 팔도 몸 아래에 둔다.
- 몸과 장치를 따로 움직이면 몸에 가려졌던 장치가 드러난다. 장치는 가려진 곳까지 이어 그린 판에서 오린다.
- 바닥까지 닿는 머리카락은 고개와 함께 돌리면 갈라진다.
- 자세 그림(뒷모습으로 겨누기, 당기기)은 가려져야 할 팔이 앞으로 나오는 해부학 오류가 판을 거듭해도 안 잡힐 수 있다(Arrowhead 주인공). 지시에 "무엇이 무엇에 가려지는지"를 따로 적고, 두 판 안에 안 잡히면 가늘고 움직이는 것(시위, 화살)은 그림에서 빼고 코드 선으로 그려 몸 뒤에 정렬하는 쪽을 제안한다.
- 이미지 생성 안전 시스템이 안 하나를 막을 수 있다(이유는 알려 주지 않음). 막힌 안은 노출과 신체 묘사 낱말을 줄여 한 번만 다시 뽑고, 그래도 막히면 그대로 보고한다.
- Windows에서 Claude의 뒤에서 도는 Bash로 `codex exec`를 띄우면 Codex `hooks.json`의 `.cmd` 훅 때문에 이벤트마다 cmd 창이 깜박일 수 있다. 처음 부를 때 사용자에게 한 줄로 알린다.
- 그림을 만드는 세션과 코드를 고치는 세션을 나눠 돌리면, 그림 세션은 그림 폴더와 아트 문서만 고치고 에디터에서 씬과 prefab을 저장하지 않는다(unity 규칙 "병렬로 돌릴 때").
