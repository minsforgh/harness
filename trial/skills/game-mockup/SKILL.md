# game-mockup

상태: 시험 중. 쓸 때마다 아래 "시험 기록"에 한 줄 남긴다.

화면 배치는 말로 정하면 서로 다른 그림을 떠올린 채 합의하게 된다. 시안 한 장을 놓고 "이 자리, 이 크기"로 말하면 고칠 점이 바로 나온다. MaxwellDemon(체온 HUD, 능력 칸)과 Arrowhead(전투 화면 전체 배치)에서 이 반복이 먹혔다. 시안은 결정을 돕는 그림이고, 결정의 원본은 설계 문서다.

## 언제 쓰나

- 화면의 자리, 크기, 무엇을 함께 보일지가 아직 정해지지 않았을 때.
- 시간에 따라 변하는 표시(쿨타임, 체력 감소, 조준 중 변화)를 비교해야 할 때. 정지 그림으로는 모양 논의가 안 된다.
- 쓰지 않을 때: 사용자가 모양을 말로 다 정했다(MaxwellDemon에서 9번 중 5번). 그때는 바로 만들고 캡처로 확인한다.

## 순서

1. **질문 정하기**: 이 시안이 답할 질문을 한 줄로 적는다(예: "주인공을 화면 어디에 얼마나 크게 둘까"). 질문이 없는 시안은 장식이 된다.
2. **재료**: 설계 문서에서 화면에 나와야 할 것을 모은다. 실제 게임 캡처가 있으면 배경에 깐다(Unity는 unity CLI의 `capture game_view`. 저장 경로가 프로젝트 밖이면 거부되고 Assets 아래에 저장되니 옮긴다). 정식 아트가 없는 자리는 단순 도형이나 SVG로 두고 "임시"라고 표시한다. 정해지지 않은 문구도 그렇다고 표시한다.
3. **시안**: `templates/mock.html`로 단일 HTML 파일을 만든다(외부 파일과 CDN 없이 더블클릭으로 열림).
   - 위치: 프로젝트 값(AGENTS.md "값" 표의 시안 칸)이 있으면 거기, 없으면 `docs/mockups/<화면 이름>.html`. 계정에 붙는 Artifact는 사용자가 원할 때만 쓴다.
   - 1920x1080 게임 화면을 창에 맞춰 줄여 보인다. 안전 여백과 화면 비율은 프로젝트 값을 따른다.
   - 안은 2~3개, 서로 다른 배치나 강조를 시도한다(색만 바꾼 안은 하나로 친다). 질문이 하나로 좁혀졌으면 한 안에 상태 버튼만 둔다.
   - 상태 버튼(조준 전/중, 쿨타임, 피격)과 자동으로 값이 변하는 흉내를 넣는다. "맞기" 같은 버튼으로 사건을 일으켜 보게 한다.
   - "자리 설명" 토글로 각 영역이 무엇인지 겹쳐 보이게 한다. 처음 보는 사람이 화면을 읽는 데 쓰인다.
   - 엔진으로 옮길 수 있는 표현만 쓴다. 규칙은 `mock.html` 머리 주석(Unity uGUI 기준)이 정한다. 다른 엔진이면 그 엔진에 맞게 주석을 고쳐 쓴다.
4. **보여 주기**: 파일 경로를 링크로 알리고, 다른 기기에서 보고 있을 수 있으면 SendUserFile로 보낸다. 무엇을 시도했는지 안마다 한 줄로 말한다.
5. **반복**: 사용자의 의견대로 같은 파일을 고친다(바뀐 부분만). 버린 안은 지우고, 남긴 안의 변화는 파일 맨 위 "고친 기록" 주석에 한 줄씩 남긴다. 의견이 화면을 넘어 규칙 설계로 번지면 시안을 멈추고 그 결정부터 정한다(필요하면 grilling).
6. **확정**: 정해진 것(자리, 크기 비율, 함께 보일 것, 버린 방향)을 설계 문서에 옮겨 적고 시안 파일을 가리킨다. 시안 파일은 커밋해 둔다(구현과 캡처 비교의 기준).
7. **구현 뒤 비교**: 구현했으면 같은 상태의 게임 화면을 캡처해 시안과 나란히 보고(시안은 헤드리스 Chrome으로 같은 폭으로 찍는다: `chrome --headless=new --screenshot=<png> --window-size=1920,1080 --virtual-time-budget=3000 file:///<시안>`. 시간 예산을 빼면 CSS 전환 중간이 찍히고, Windows에서 Edge 헤드리스 캡처는 파일이 안 남았다), 눈에 띄는 차이(위치, 크기 비율, 색, 글자 크기)를 고친다. 3번 안에 못 맞춘 차이는 그대로 보고한다.
8. 시험 기록을 한 줄 남긴다.

## 함정

- 밝은 배경 위 시안에서는 어두운 표시가 잘 보여도 실제 어두운 게임 배경에서는 묻힌다. 실제 캡처를 깔거나 게임과 같은 밝기의 배경을 쓴다(MaxwellDemon 체온 띠).
- HUD 모서리 부품은 화면만 보지 말고 그 씬의 카메라 범위와 캐릭터가 서는 자리를 같이 봐야 한다. 시안 배경에 캐릭터 자리를 그려 둔다(MaxwellDemon 능력 칸이 시작 자리를 덮음).
- 그라데이션, 그림자, 빛 번짐을 처음부터 빼 두면 엔진으로 거의 그대로 옮겨진다. 쓰면 어떤 스프라이트가 될지 주석으로 적는다.
